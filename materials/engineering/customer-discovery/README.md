# Customer discovery and demo communication

Read the fictional operator brief, then complete the three blank learner documents. Keep every unverified belief labelled `HYPOTHESIS` until the fictional operator evidence supports or rejects it. This exercise does not authorize outreach or represent a real customer.

## Prerequisites

- A Markdown editor
- No account, network access, or external message

## Work sequence

1. Write discovery questions and evidence rules in `discovery.md`.
2. Convert validated needs into observable acceptance criteria in `acceptance.md`.
3. Prepare a truthful operator demo and failure-language plan in `demo-communication.md`.

There is no automated correctness test. The repository meta-test only checks that the fictional brief is present and each learner document remains explicitly hypothesis-labelled at starter state.

## Return evidence

Return the three completed paths, a hypothesis/evidence/decision table, rejected assumptions, and the exact demo scenario you would run. Record the reviewer and review date separately; drafting alone is not customer validation.
